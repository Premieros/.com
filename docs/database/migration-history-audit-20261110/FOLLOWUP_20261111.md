## Guarded 55-file candidate

`scripts/db/candidates/reconcile-history-exact55.mjs` is separate from the migration runner and previous three-file P0 tooling. There is no CLI or hosted execution path. It accepts only a localhost PostgreSQL connection as postgres, defaults to a read-only transaction, pins the immutable original Git matrix bytes and every canonical SHA-256, and refuses any nonunique/nonexact scope.

Before inserting metadata it locks both ledgers, verifies custom-ledger columns/defaults/constraints/RLS and absence of triggers/rules/inheritance, and verifies each original remote name and single-statement hash. All preflight checks complete before the first insert. Existing matching acknowledgements are preserved; version/name/checksum conflicts abort. It inserts only version/name/checksum into `public.schema_migrations`, verifies all pre-existing rows and the complete remote-history rows are unchanged, and commits atomically. It never executes a migration statement or business RPC.

Disposable PostgreSQL tests cover 55 inserts, read-only mode, retry idempotency, partial acknowledgement, checksum/name conflicts, missing/changed/extra remote statements, schema drift, RLS/trigger rejection, concurrent-writer lock failure, and rollback after **54 successful inserts when the 55th fails**. PostgreSQL sequence increments are not transactional; the failure test intentionally confirms sequence advancement while all inserted rows disappear. This must be considered in any future production execution plan.
